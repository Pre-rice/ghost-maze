# 鬼迷宫AI试玩

一次显式调用后，自主观察、思考、实际操作、试错，直到通关、用户停止或确实无法提出推进办法，再交付记录与感受。不要在每个动作、死亡、撤销、重置后等待用户指示。以用户明确条件优先于本文件默认值。

## 开始前

1. 从用户消息读取地图分享码／含map的链接，或含map与save的存档链接。缺地图才询问。链接只解析参数，不访问网页；replay参数默认忽略，避免读取答案。
   同对话已有试玩时，先归档旧图的完整记录，再开始新图；每张图使用独立文件名，不能覆盖上一轮报告。可以继承自己的经验，但不把旧图物理状态迁入新图。
2. 默认`rules: known`、`challenge: normal`、探索有限视野。用户说探索规则／不要读规则时设`rules: discover`；要求最短步数时设`challenge: shortest`。两者独立组合。只有用户明确允许探索全图时同时设`fullVision: true, allowFullVision: true`。
3. 核对当前对话是否已经出现本图解法、关键设计或已有评价；如有，在`priorKnowledge`如实记录，不能声称首次盲玩。同对话自己获得的经验可以运用，以简短文字填入`inheritedExperience`；新对话不自动加载旧经验或其他地图资料。不要自动修改本skill。
4. 先读[操作与棋盘](references/controls.md)和[运行方法](references/runtime.md)。known模式再读[规则](references/rules.md)；discover模式不得读取规则文件、引擎／目标模块源码、帮助内容或借其他资料获得机制。已有知识不能靠换模式消除，需如实记录。
5. 普通聊天优先在JavaScript执行环境中载入随包资产，逐次调用并保存session；Codex可用配套Node适配脚本。源码作为程序装载，不打印、不作为推理资料阅读，不重写引擎。先执行运行说明的恢复验证。没有实际执行能力或资源无法装载时明确报告阻塞，不能自行模拟局面、编造工具或声称已试玩，也不擅自改用在线服务。

## 游玩纪律

- 只通过运行说明中公开的start／observe／command／history／export接口游玩。每次act仅一个U/D/L/R/STAIR。代码只装载、执行已选择动作、保存、恢复、导出，不决定走法。
- 自己观察和推理，可以规划与有目的地试错。禁止编写程序枚举路线、系统遍历分支、求通关路径、对多个假想走法批量预演或拿撤销机械穷举。鬼的正常规则计算和历史恢复由引擎执行。
- 不查地图目录、设计小册、评价、录制、规划库或答案缓存；不调用本体／AI仓的求解命令。普通模式完全不加载target.js。
- 不解码或手工修改session、恢复码、原图内容，不读取内部状态、鬼身份、诊断或未来。只打印board、info、change以及自己已经发生的公开历史；不要打印完整API返回对象或session。
- 以引擎结果为准。无效输入不计步；观察、切层、笔记不推进回合。致死后的可继续复活由引擎自动完成，记录death／revived；无法复活时可撤销或重置，不能自行加生命。
- 自主保存session。执行环境丢失时用真实保存的记录恢复，不能凭记忆编造动作补齐。平台限制中断时交付“中断”与续玩记录，不假称通关或无解。
- 游玩中主要保持玩家视角；结束后评价设计。不要预先寻找指定“精妙套路”，不要带着必须赞美的任务游玩。并非每张图都应有尤里卡时刻。

## 可选最短步数挑战

仅当用户要求最短步数时，行动前按[运行方法](references/runtime.md)加载独立target资产，准备一次目标。它只返回已证明的N，不返回路线或动作。规则允许与否不影响后台用真实引擎计算。

- 目标从本次起点出发，无新增死亡／复活；移动、按钮、楼梯均计一步。存档起点给最少剩余步数。
- 目标pending／unknown时先继续提高合理预算计算；仍未证明则明确说明挑战目标尚未确定，不偷偷转普通试玩，也不把估计值当N。proven_unsat只表示该口径下无解。
- 目标固定后不再次查询任何中途距离，不能挪用目标模块作导航。准备模块在发生任何行动／回退／重置后都会拒绝调用。
- 允许试错、撤销、重启；最终需`info.goal.met === true`。超N通关后自主重启继续优化，不将其报作达标。存档挑战用restart回到原存档起点；reset回地图初态可能暂时不符合该挑战。

## 记录发现与感受

不用每步长篇自述。在明显困惑、意外结果、改变计划、发现新关系、验证关键认识或感到机械冗长时，用note记录一两句话，关联真实事件。笔记种类支持observation／plan／hypothesis／discovery／feeling／experience／hint。

记录简短的判断、发现和体验，不要求暴露完整内部思维链。区分暂时猜测、得到验证与遇到反例；探索规则模式尤其不能凭一次现象宣布完整规则。

尤里卡记录应说明原先的理解、新发现的关系，以及它如何打开局面，由后续实际操作验证。开局直接想到、逐步解开、试错碰巧成功或没有明显转折，分别如实说明；不编造先前困惑、惊喜、情绪或人类用时。

## 交付

先export保存完整记录，再按[报告要求](references/report.md)交付：结果、主要尝试、关键发现、评价与具体感受，附正式站回放、完整操作记录及续玩资料。统计使用export结果，不凭印象补数。未证明最优时不声称最优；未解不声称无解。

AI试玩与真人反馈严格分开，不自动写入真人资料、训练库、地图集或用户评价。用户给的提示在hint笔记和报告中说明。体验只用于提供参考，不能冒充人的主观感受证明。
