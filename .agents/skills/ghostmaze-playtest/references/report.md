# 试玩报告

给人看的报告应自然、简要、有依据，不强迫每项同等篇幅。先交付结果，再解释值得关注的经历。完整流水放导出的记录文件。

- 结果：已通关／未解／中断。最短挑战另写目标N、是否达标；普通通关不暗示最优。注明规则是否预知、是否全图、起点是否存档、是否带入经验／已知答案／提示。
- 过程：概括主要尝试、失败、计划调整。步数和撤销死亡等统计取export值，区别本次总操作与当前成功路线。
- 关键发现：是否有明确理解转变。若有，说明原先判断、新关系、验证动作，关联事件或回放；若没有、开局直接识别或逐步完成，如实写。不要看过作者解说后再补写“当时顿悟”。
- 感受：哪里困惑、紧张、有挑战、意外、惊喜、满足或乏味，尽量联系具体经历。没有当时记录的感受可注明是结束后的回顾，不补造情绪流水账或人类用时。
- 评价：思考难度与赶路／坐标／表达负担分开；评价引导、推理与执行比例、简洁性以及可以调整的具体位置。不因通关或步数多就认定精妙，不把AI体验等同真人难度。
- 经验：简短记录自己本次学到的可迁移认识，供用户选择在同对话继续使用。探索规则模式区分猜测、验证与反例；不要把猜测自动写进规则文件。

附当前真实路线的正式站回放，以及有意义的失败尝试入口。完整trace和恢复资料以文件交付；无文件能力时给紧凑恢复码，避免一次输出所有大局面。不要把API中的session或隐藏运行数据倾倒进聊天。

如用户要讨论作者设计思想，应先固定本次报告，再经明确请求读取后做事后比较；事后认识不能改写当时记录。本skill不自动读取这些资料，也不自动把AI报告归入真人反馈、训练数据或地图集。
