## 页面与状态

网站采用原生模块的单页应用，无框架或新增依赖。游戏与编辑器一起加载，首次切入编辑无需额外资源请求；不是点击编辑后再动态下载。主入口游玩、编辑共用 `/?map=…`，回放仍用 `&replay=…`；地图集 `/maps.html`、帮助 `/help.html` 为独立分享地址，三者使用同一应用壳。旧editor.html入口进入编辑后统一根网址。

应用内导航保留游玩controller、编辑workspace和独立回放历史；浏览器前进后退恢复对应上下文。编辑只复制原图，不把游玩局中的开门、取物或鬼位写进草稿。试玩独立使用草稿快照；返回编辑保持工具、观察位置、选中元件及撤销栈。编辑求解回放返回编辑及弹窗，游玩求解返回原局及弹窗。回放加载该步若源自编辑，仅建立临时试玩，不覆盖草稿。

| 模块 | 职责 |
| --- | --- |
| app.js | 同页导航、网址、上下文与历史 |
| main.js／GameController | 游玩、死亡恢复、存档与回放 |
| editorMain.js／editor/workspace.js | 编辑手势／视野、事务、撤销、尺寸、选择与移动 |
| EditorDocument | 编辑器唯一地图数据，保留历史regular读取和生成器依赖 |
| GameLogic | 唯一物理引擎，运行、求解与AI共用 |
| solver | 可暂停最优搜索、鬼轨迹前缀归并及回放入口 |
| viewSlice／renderer | 只读投影与画布；钥匙在鬼上 |

运行期物理权威仍为MapDefinition与GameState；编辑权威为workspace中的EditorDocument，视野／选中状态不进入地图码。全局stairs与各层同坐标保留；不按各层分别平移坐标。

编辑统一自由方式，无常规／自由选项。未编辑的旧常规码及初始揭示保留；实际编辑后以新自由图保存。绘单向门时箭头朝指针所在侧，拖动跨侧沿原墙改向；墙／玻璃笔划沿起始横线或竖线连续绘制。小幅触控抖动算点击，取消或双指导航撤销临时笔划；右键仅作便利，所有操作有触屏入口。

宽高独立、1～20的工作区按真实包络居中，内部8～20容器保持旧分享格式。扩展不清空，裁切预告损失并可撤销；区域与整图平移同步关联元件，跨层楼梯要求全层移动。出生点／终点不能复制成多个；叠放元件可独立选择移动和移除。未完成草稿本机保存，合法编辑才即时更新网址；存储不可用时明确只保留当前标签。

新编辑草稿默认死亡循环，左侧死亡循环、右侧探索；载入旧图不改玩法。随机生成固定探索，只提供原大小、探索初始生命；原随机算法和出生房间保持。主题仍深浅两档。地图集十三图原顺序、无图和解法剧透，三项基本数量与试玩入口保持。

死亡循环及回放全图、无视野开关与周围鬼数；探索保留。页面标题固定，致死回放仅将玩家绘到出生点，不改历史实际死亡位置。回放不提供随机、重置或求解按钮。

## 唯一地图形状

```js
{
    width, height,                    // 8～20
    editorMode: 'regular' | 'free',
    gameMode: 'exploration' | 'death-loop',
    initialHealth,                    // 探索生命，默认 5；无体力
    multiLayerMode, layerCount,        // 1～10 层
    layers: [{
        hWalls, vWalls, activeCells,
        ghosts: [{ x, y, id }],
        items: [{ x, y, type: 'key' }],
        buttons: [{ x, y, direction, letter }],
        endPos, customStartPos
    }],
    stairs: [{ x, y, layer, direction: 'up' | 'down' }]
}
```

各层只保留一份数据，恰有一个出生点；regular 的默认出生点经装配写入第零层，free 明确设置。允许每层一个终点，至少一个终点才可游玩或分享。鬼顺序保留，不按压缩需要重排。

既有 JSON 可从单层顶层结构或一致的第零层副本接入，但不能猜测冲突。若顶层与第零层不同，或层内楼梯与全局楼梯不同，严格拒绝。保留原件，在总目录说明，不擅自覆盖一份。

所有游玩、编辑导出、AI 和分享入口使用 `validateMapData`。门和玻璃仅能在两侧都为活动格的内部墙段上；外圈及虚空接壤始终显示为实墙，不能通过编辑放置机关，非法原始输入明确拒绝。EMPTY边界沿用既有隐式墙表示以保留合法旧码与操作码校验；静态装配防止遗留边界机关。无终点的机制单元仅在显式 `requireEnd:false` 的研究入口允许。数字门钥匙要求为无符号 32 位整数；探索生命为 1～4294967295。

## 墙体与机制

横墙为 `(height+1)×width`：`hWalls[y][x]` 是格子上墙，`hWalls[y+1][x]` 是下墙。竖墙为 `height×(width+1)`：`vWalls[y][x]` 是左墙，`vWalls[y][x+1]` 是右墙。取方向墙复用 `getWallInDirection`。

| 墙类型 | 值 | 玩家行为 |
| --- | --- | --- |
| EMPTY | 0 | 可过 |
| SOLID | 1 | 阻挡 |
| DOOR | 2 | 自由通行，鬼不能过 |
| LOCKED | 3 | 钥匙足够可过，不扣钥匙，门消失为 EMPTY |
| ONE_WAY | 4 | 仅匹配方向可过 |
| GLASS | 5 | 不可过但可视 |
| LETTER_DOOR | 6 | 当前开时可过；按钮切换全部同字母门 |

墙判定用 `WALL_TYPES.*`，非空写 `!== WALL_TYPES.EMPTY`。墙参数分别为 keys、direction、letter 和 initialState；动态字母门另有 currentState。

成功移动、按钮、楼梯都计一步并推进鬼；无效输入不计。按钮依附实墙或活动区边界，必须通过合法性检查，不能以求解成功代替。楼梯必须在相邻层同格有反向配对，同层同格不可重复；空格使用，操作无需区分上下。

鬼争同一格时，操作后仍能看到玩家者优先；最高优先级相同者共同入格，夹击死亡只扣一次生命。编号与列表顺序不参与决定。

玩家与鬼的射线都只通过连续活动格，虚空中断视线，不能隔空追击。鬼依靠同行／同列直线视野，看到后走最短路一步；失去目标后的短暂追踪无持久记忆，通常不巡逻。鬼不能穿普通门、锁门、单向门或玻璃，但能透玻璃看。已开字母门对玩家和鬼的射线均透明，鬼可以通过。配对楼梯格互为相邻格，双方站在两端时即可互见；玩家抵达楼梯口，另一端的鬼当步追来。上下楼时，原层鬼追旧位置，到达层鬼追新位置，各只走一步；本回合刚到楼梯口的鬼不能再跨层。

## 历史、复活与回放

- 唯一动作名：`U/D/L/R/STAIR`。原地按钮记实际方向，不猜前后局面；点击寻路记实际逐步操作。
- 操作是可分享的持久信息；局面仅为可重建临时缓存。默认每 32 步锚点和近期局面，初态与当前态保留，预算 16 MiB；不删除操作来省缓存。
- 存档是本局步号，不写 localStorage。撤回后新动作裁未来及未来存档，主动复活后不能撤回跨复活边界。
- 探索碰鬼扣生命，复活回出生点但保留物理变化与累计操作；下一操作从死亡状态推导复活，复活不占回放步。
- 死亡循环碰鬼判死，复活重置物理／步数／路线／存档，保留探索且循环加一，只保留最后轮。
- 两模式死亡可撤回致死步，也可回上一个更早存档。重置地图清操作、存档、探索及全部物理变化。
- 回放入口是 `?map=地图码&replay=操作码`，默认暂停、全图，五档速度，支持跳步。游玩和回放标题只显示页面与模式，不附加死亡或通关信息；不显示重置地图、随机生成按钮。操作码不写局面、探索、循环、版本或时间。
- 确认加载第 N 步后：探索视野替换为路线视野；死亡循环同图循环加一、探索取并集，并作为该轮缓存的基础视野，撤回仍保留。不同图不迁移探索。存档清除，路线换为前 N 步。
- 探索模式的全图开关只影响显示，不污染探索；死亡循环固定全图也不改探索记录。回放致死帧只把玩家画在出生点，跨层死亡显示出生层；实际历史保留死亡位置、生命及机关状态。死亡／胜利步准确加载，不强行变为存活。

## 分享与错误处理

完整协议见 [docs/share-codes.md](share-codes.md)。地图码与操作码无格式版本，无旧码解码器或启发式兼容。当前码为 Base64URL，无末尾等号；是否压缩和内容表示由控制位确定。

生成先完整校验，再编码并解回核对；非法类型、悬空按钮、楼梯冲突、数值超界、截断或多余尾数据干净失败。内部位流非法统一抛 RangeError，上层返回可显示错误，不产生 NaN 或死循环。

AI 通过同级本体模块直接使用规则，以 `ghost-maze-ai/engine.lock.json` 的文件内容锁核验。本体 core 改动后在 AI 仓运行 `node scripts/lock-engine.mjs`，并做相关证书和回归核验。搜索可保留索引、队列、启发式，禁止新增重复物理规则。

常量使用 `constants.js`，localStorage 经 `safeGet/safeSet`，prompt 经 `askForInput`。历史证据与导入工具不是运行时死代码，不能因旧规则字段而擅自删除。

## 地图与生成

首页随机生成固定探索，仍为原单层DFS加随机点，不保证可解或谜题质量。求解从地图初态出发，无伤无复活，目标为有效动作T最少；始终使用共同GameLogic。小图用BFS，大图用有一致乐观距离下界的A*，收齐全部最短前继；无鬼图只需一条已证明最优的路线代表唯一鬼轨迹。

不同解法按所有层每步可见鬼位归并，保留什么时候动和停，不按编号或列表排列区分。完整物理状态仍含玩家、钥匙与门；鬼轨迹只在最短前继图上归并，不直接合并搜索局面，也不替代AI全部最优安全审查。回放只为代表路线生成，最短步数与整理进度分别展示，未知可继续、暂停保留同图工作线程。结果缓存与原图绑定，实际改图失效。

鬼寻路缓存按静态层、权威墙态和目标格分组，不写入物理局面；保留上右下左的原等长路选择。当前十三图和旧十五图的全部最优动作、107615次可达物理后继及原码／回放保持。[交付与验收](archive/delivery/site-optimization-20261014.md)。

后续每张新图交付前：合法性 → 新地图码往返 → 共同规则证书重放 → 操作码往返 → 总目录。浏览器集中验收规则／交互升级及新增机制，不再为每张已核验 AI 路线反复整段浏览器通关。

golden 仍在 `test/golden/`；更新应保留规范地图与当前码闭环、逻辑快照，不沿用旧码兼容断言。历史作品、证据和真人原录制保留，迁移结果另存。
