# 死亡循环与回放显示调整

2026-10-13。本轮仅调整显示，页面仍独立；地图设计和训练暂停。

## 产品结果

- 死亡循环及其回放直接展示全图，不显示“全图视野”开关或“周围鬼数”。探索模式及其回放保留这两项，返回游玩恢复原来的视野选择。桌面死亡循环的空选项行消失，手机保留方向按键设置。
- 回放标题只显示回放与模式，不附加“已死亡”“已通关”；回放不显示“重置地图”“随机生成新地图”。
- 致死回放帧的玩家画在出生点；跨层死亡自动显示出生层。历史仍保留真实死亡位置、生命和物理状态，加载该步仍是死亡局面，不自动复活。前后跳步、探索死亡后的继续操作、返回原局均已核验。

## 独立页与单页的取舍

合并本身不必然拖慢主页；关键是是否在首页一次加载其他功能。当前本地浏览器实测加载资源：游玩页脚本约267KB原文，编辑器相对游玩页独有脚本45,673字节、两个脚本请求；地图集独有脚本4,145字节，帮助无额外脚本。这些是未压缩资源量，不是正式站耗时或公网性能测试。

| 方式 | 首页负担 | 第一次进入编辑器 | 使用取舍 |
| --- | --- | --- | --- |
| 独立页面 | 不加入编辑器独有部分 | 加载新页面与独有代码；公共资源可使用浏览器缓存 | 游玩与编辑草稿可同时保留、并排打开，状态隔离清楚 |
| 单页一次全加载 | 增加其他页面资源及处理成本 | 已预先加载，切换可以更快 | 首页先承担所有功能的成本，仍需分别管理游玩与草稿 |
| 单页按需加载 | 可接近当前首页 | 仍下载并初始化编辑器，但可省去新页面重建 | 后续切换顺畅，必须保证游玩、草稿和回放状态各自保留 |

目前建议保留独立编辑器；它为保留原局和草稿提供简单可靠的隔离，新增资源量不足以单凭这个理由全面合并。若主要诉求是频繁同页切换，按需加载的单页值得考虑；第一次打开独有功能也仍有成本。地图集、帮助可以在需要时同页打开，但这主要是导航体验选择，当前资源很轻。没有测量正式站网络瓶颈，不宣称本地结果证明线上总耗时。

原来的独立页决策着重保护原局与草稿；现在资源检查补充了加载成本依据，尚无必须替换已确认方案的证据。本轮只讨论，未合并页面或擅自增加预加载。
