| 紧凑排列、去掉多余分割线 | 缩减编辑行间距，去除编辑设置区分割线；仍保留整体面板边界 |

## 验收与此前遗漏

本轮23项浏览器专项通过，含桌面及触控模拟、320–1920px布局、十层上限、全部四边越界、图像逐字节对照、淡入淡出与Tab、增删层撤销重做。两仓cloud:check通过：本体23文件、AI参考及旧测试、共同规则锁、两个种子、22个HTTP入口和代理检查。新增范围外悬停回归通过。物理规则、分享码和十三图未改，无生成或训练。

上轮23项检查覆盖了规定切层与手势，没有覆盖地图范围外悬停；其通过不能证明不存在这次的绘制缺陷。本轮先记录修复前真实异常和残留偏移，再验证连续操作及图像不变。用户截图中的旧楼层后缀与当前预览源不一致，未无依据归因于缓存；本轮另核对打包文件和源码一致。私有预览由Sites原生部署结果确认，未自动打开侧栏、未检查正式站；浏览器验收使用本地同一源码，未声称真机验收。

详细测量见AI仓[本轮证据](https://github.com/Pre-rice/ghost-maze-ai/blob/preview/site-optimization-20261014/data/manifests/editor-layout-browser-20261015.json)。旧证据与评述保持。

## 最新居中与控件调整

本节按用户最新决定覆盖此前“电脑底部楼层栏”的位置约定。此前留在下方并预留高度是为容纳楼层控制；现在明确改回两栏之间，因此删除底部预留，给楼层栏保留64px两栏间隔，地图本身垂直居中。手机仍保留地图下方楼层栏，游玩、回放、编辑不因切栏目改变地图区域大小。

| 最新要求 | 已落实 |
| --- | --- |
| 地图与楼层居中 | 电脑地图按整页中心对齐，楼层栏在两栏间垂直居中且不覆盖内容；手机楼层在上下布局中间 |
| 四栏目稍加间距、不增宽 | 仅栏目间距2→6px，原按钮内边距与文字大小保持 |
| 空地图也有框 | “加载地图以开始”恢复边界框 |
| 编辑行间稍宽且收起草稿不溢出 | 编辑主要行距9→12px；1280×647及更高的桌面收起草稿不出现滑条。手机保持原地图区域，空间不足时只在面板内滚动 |
| 可撤销操作不确认 | 删除顶层、改单层、缩小范围直接执行；裁切内容、楼层和楼梯都由原撤销历史完整恢复，清空和填充同样直接执行 |
| 方形楼层按钮、图形居中 | 电脑36×36、手机34×34；加减号和所有弹窗关闭按钮采用几何居中图形；已有无障碍名称保持 |
| 工具图像稍大、按钮不变 | 桌面图像22→24px、手机21→23px；按钮仍40／38px，按钮元件原有内容居中调整保持 |
| 清空／填充名称明确 | 改为“清空方格”“填充方格”，与“清空元件”同样作用于当前层 |
| 游玩／回放视野一致 | 共享同一个开关，初始关闭；进入回放不再自动打开。死亡循环仍固定全图并隐藏开关 |
| 消除双框 | 元件浮框去掉外壳边框；输入框和Tab焦点只改变原有边界，不产生偏移的第二层外框；淡入淡出及数值池保持 |
| 随机生成卡顿 | 生成与分享码压缩移到后台，立即显示“正在生成”，防重复提交；关闭可取消，过期结果不会替换当前图；后台加载失败明确提示并恢复重试 |

随机生成旧实现实测8／10／20共240次，未复现用户提到的长期卡死；单项最大生成约24ms、编码约27ms，不能据此断言设备上的唯一原因。可确认旧流程同步占用界面线程且没有等待反馈，本轮先消除这两个风险，保持原生成规则、地图格式和共同规则锁。新版连续15次生成成功；人为增加700ms后台计算时界面仍响应，模块加载失败可重试，慢速加载可取消。测量来自本地环境，不当作远端或真机耗时承诺。

本轮24项专项、两仓cloud:check通过：本体23测试文件、AI参考与4份旧测试、规则锁、原种子、22个HTTP入口及代理来源检查。覆盖769–1920px电脑居中、320–768px手机、十层、撤销、视野共享、单层边框、图形中心及生成成功／取消／失败。仅做合成验收，未开训练、未改十三图、未写人类反馈，正式两个main与远端一致且未更新。
