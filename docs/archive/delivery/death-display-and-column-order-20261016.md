## 后续修复：通关入口被最优解路线污染

用户复现：通关后点“查看最优解”，打开某条最优解回放（URL 变为 `?map=…&replay=…`），再点“游玩”标签回到游玩，“查看回放”显示的是那条最优解而不是本次游玩的回放。

原因：打开最优解只换了 `replaySource='external'` 和 `game.replay`，回到游玩列时来源标记、求解返回点与 URL 都还留着；回放列因此继续显示外部路线。“查看回放”按钮原先直接切栏目，没有重新声明“要本次游玩的回放”。

修复：新增 `playthroughReplay()`，“查看回放”改为先复位 `replaySource='current'`、`replayDirty=true`、`solutionOrigin=null`，把 URL 收回 `?map=` 再切回放，强制重新装载本局路线；“返回游玩／返回编辑”同时清掉求解返回点，回到游玩后回放列也是本局路线。被动切栏目仍保留外部回放链接的内容（原行为不变）。

浏览器复核：复现场景下“查看回放”由 `DR`（最优解）恢复为 `RDR`（本局），URL 收回 `?map=`，返回按钮隐藏；“返回游玩”后回放列同样为本局路线；直接通关无求解时的“查看回放”、以及 `?map=…&replay=…` 外部链接跨栏目保持，均未回归。`npm test` 27 个测试文件通过，试玩包逐字节核对通过。
