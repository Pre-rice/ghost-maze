全图视野是显示选项，不会把全图永久写入已探索区域。关闭后恢复按实际移动积累的视野。

## 2. 历史、存档与死亡恢复

每次有效操作发生时直接记录方向或楼梯操作。方向键原地触发按钮也记这个方向，无需另记按钮字母；点击寻路展开为实际执行的逐步方向。取消通过前后局面猜测新操作的做法。

操作日志负责重建过程，缓存负责快速恢复。存档点是本局的步号标记，额外保留该步的临时局面；刷新不恢复进度。地图与显示设置的既有存储不扩展为游戏进度保存。

撤回或回存档后，观看旧路线本身不改记录；从该位置走出新操作时裁掉旧未来及未来存档。撤回不跨越主动复活的边界。

| 死亡后的选择 | 行为 |
|---|---|
| 回到上一个存档点 | 两模式都有；恢复本命最近的更早存档及对应局面、步数和视野。没有存档时明确显示不可用 |
| 原复活：探索 | 尚有生命时保留原规则：回出生点，保留剩余生命、已改变的地图与物品状态；本命旧存档清除 |
| 原复活：死亡循环 | 重置位置、鬼、物品和门，步数归零，保留已探索区域，循环加一；清除上一轮操作、缓存和存档 |
| 重来 | 重置同一地图，生命／循环、步数、物品、门和探索回初始状态；本局操作、缓存和存档全部清除 |

**死亡循环只保留当前／最后一轮路线。探索模式保留从开局到当前的有效操作。** 两者不能机械地都截成最后一命：探索复活后，先前拿到的钥匙、打开的门和鬼位仍影响当前局面，仅从原图重放最后一命会还原错。

探索回放仍只使用五种操作。若前一步死亡、仍有生命且后面还有操作，共同规则先执行原复活，再执行下一操作；复活不增加步号。末步死亡就呈现死亡，单独点击复活不产生新的回放步。选步统一指“执行完该有效操作的局面”。

## 3. 同页回放与加载该步

入口固定为：

```text
游玩：https://ghostmaze.novic.cc/?map=地图码
回放：https://ghostmaze.novic.cc/?map=地图码&replay=操作码
编辑：https://ghostmaze.novic.cc/editor.html?map=地图码
```

地图码给出原图和开局设置，操作码只给出路线及地图校验。打开回放必须先有地图；缺地图或错配时说明原因，不生成一个没有地图的回放入口。分享无需录制服务器、编号或账号。

回放默认自动播放并显示全图，提供播放／暂停、前后一步、步号输入与滑条，以及 `0.25×、0.5×、1×、2×、4×` 速度。第 0 步是初始局面；切速只改变播放间隔，不改变规则。到末步自动暂停。

关闭全图后，从地图初态沿操作序列实时计算已探索区域，不还原录制者此前几轮探索。观看、选步和切速保留当前游玩状态；只有“加载该步”执行替换。

点击“加载该步”先暂停，弹出：

> 是否加载第 N 步到当前局面？这会替换你当前的游玩状态，并清除当前存档。确认加载／取消。

确认后的处理：

| 内容 | 探索模式 | 死亡循环 |
|---|---|---|
| 玩家、鬼、钥匙、门、胜负 | 使用回放第 N 步准确还原的状态 | 使用回放第 N 步准确还原的状态 |
| 步数 | N | N |
| 探索视野 | 使用回放从第 0 步到 N 步产生的视野，替换当前探索 | 当前同图探索与回放第 0 步到 N 步产生的视野取并集 |
| 循环 | 不适用 | 本次加载算新循环：当前为 6，加载后为 7；从初始 0 加载则为 1 |
| 操作和存档 | 当前记录被回放前 N 步替换，存档清除 | 当前记录被回放前 N 步替换，存档清除；这 N 步属于新循环 |

死亡循环加载时，原有探索作为新循环的基础视野保留，随后沿该路线产生新探索。因此继续走、撤回到该轮更早步、再存档都保持同一套视野逻辑。缓存也必须按这个新基础重建或合并，不能撤回一次就丢失旧探索。

视野并集只适用于同一地图。若确认载入另一张回放地图，旧图探索不迁移，新地图从自身初始视野开始。加载后恢复原游玩的全图开关；回放的默认全图不带入游玩。网址去掉 `replay`，保留地图码，重新分享回放时生成当前路线的操作码。

死亡或通关的步也可以加载，并呈现相应状态和恢复入口；不偷偷把失败步改成存活状态。取消加载后，当前局面、历史和存档都保持原样。

## 4. 新地图码：完整机制

### 4.1 保存什么

地图码保存：尺寸、编辑类型、玩法、探索初始生命、唯一出生点、每层活动格和初始墙、鬼、钥匙、按钮、终点、配对楼梯。

不保存：体力、当前局面、操作、存档点、探索历史、循环次数、动画时间、主题、名字和说明。名字与来源放在地图总目录。

地图只有一份各层数据，第 0 层不再同时存顶层副本。直接试玩、生成分享码、AI 和回放都使用这份统一地图及作者开局设置，不由主页残留设置覆盖。

### 4.2 怎样缩短

| 信息 | 新表示 |
|---|---|
| 尺寸 | 宽、高各 4 位，保存尺寸减 8；覆盖当前 8～20 的范围 |
| 编辑类型、玩法 | 各 1 位，保留常规出生房间与自由地图的规则差别 |
| 层数 | 单层用一个标志即确定；多层追加 4 位保存层数减 2，覆盖 2～10 层 |
| 初始生命 | 仅探索需要；默认 5 不写数值，自定义时写可变长整数 |
| 活动格 | 全层活动时只写一个标志；否则每格 1 位，按行排列 |
| 坐标 | 按每层活动格从上到下、从左到右编号，保存编号而非分写 x、y；13 个活动格的位置仅需 4 位，400 格需 9 位 |
| 出生点 | 只保存一次所在层和活动格编号；单层省去层号 |
| 终点 | 每层一个存在标志，有终点才写位置，支持原有多层终点 |
| 鬼、钥匙、按钮 | 每类一个存在标志；非空才写数量减一和列表，数量使用可变长整数；钥匙不重复写类型 |
| 按钮 | 活动格编号、方向 2 位、字母 5 位 |
| 数字门 | 钥匙要求用可变长整数，消除 255 后截成 0 的问题 |
| 单向门 | 方向 2 位 |
| 字母门 | A～Z 共 26 个值，用 5 位；初始开关用 1 位 |
| 楼梯 | 每对只保存一次下层编号及位置；反向配对由规则恢复，不重复存两项 |

坐标位数由活动格数量确定，数量为一时不用写位置位。鬼的列表顺序必须保留，不能为压缩重新排序。鬼标识按保留顺序重建，显示名称与生成记录不进入游戏码。

可变长整数每字节存 7 位数值，另 1 位表示是否还有下一字节；0～127 占 1 字节，128～16383 占 2 字节。资源范围明确到无符号 32 位整数，探索生命必须大于零，禁止静默截断。列表数量同时受地图合法性约束。

### 4.3 墙体的三种短表示

墙体仍按横墙逐行、再按竖墙逐行读取；墙数由尺寸确定。比较三种表示，选最终完整码最短的一种，用 2 位标志说明所选表示：

| 标志 | 表示 | 适用情况 |
|---|---|---|
| `00` | 空墙 `0`，实墙 `10`，其余 `11` 加 3 位类型编号（普通门 0、数字门 1、单向门 2、玻璃 3、字母门 4） | 常见小图与少量机关；复杂墙固定 5 位 |
| `01` | 每面墙用 3 位，类型为 0～6 | 复杂墙类型分布较平均的大图 |
| `10` | 类型 t 用 t 个 `1` 后接 `0` | 某些压缩后更短的重复墙布局 |
| `11` | 无效 | 直接拒绝 |

门参数放在本层全部墙类型之后，顺序与墙扫描一致。读到类型就知道要读什么参数，不再另存参数队列长度，也不再有 255 字节队列限制。

虚空墙仅按现有、经过验证的规范化规则处理；可能影响活动格之间视线的墙仍保留，不能简单删除所有虚空墙来缩码。

### 4.4 完整排列与外层编码

地图内容顺序固定：尺寸 → 编辑／玩法／多层／自定义生命／墙表示标志 → 必要的层数、生命和出生层 → 各层的活动格、终点、该层出生点、鬼／钥匙／按钮、墙类型、门参数 → 多层楼梯配对表。

层数、生命、出生层只在需要时写。单层没有楼梯表；多层楼梯表先写配对数量，再写每对的位置。所有位按高位在前连续排列，只在整份内容末尾补零；读完只允许不足一字节的零填充。

每种墙表示都比较原始内容、普通最高级别 `deflateRaw` 和游程策略压缩，选完整码最短的结果。同长时固定优先原文，再按 `00、01、10` 排序，保证生成规则明确。

外层只加 **1 字节控制信息**：最低位表示是否压缩，其余位必须为零，然后接内容。再转成 Base64URL，使用 `A～Z、a～z、0～9、-、_`，去掉末尾 `=`。这个控制信息用于确定解压分支，**不是格式版本**。

解码一次读取控制信息，按需解压，再按上述顺序线性读取，不尝试猜格式、逐个枚举地图或探测旧版本。不保留旧分享码读取器，不加版本号，也不维护旧码兼容。

生成端先校验，再编码，并用最终码解回一次核对完整地图及开局设置，核对通过才交付。层数据冲突、无效位置、不配对楼梯、悬空按钮、数值超界、非法类型、截断或多余数据都明确失败，避免再次出现“分享成功但无法打开”。

## 5. 新操作码：完整机制

### 5.1 默认表示：方向 2 位，楼梯另记位置

方向统一为：上 `00`、下 `01`、左 `10`、右 `11`。楼梯无需区分上楼或下楼：地图和玩家当前位置决定空格使用哪一对楼梯。

没有楼梯操作时，整个路线直接每步 2 位，四步合成一个字节；**即使地图有多层，只要这条路线没用楼梯，也不付出楼梯表开销。**

有楼梯时，从方向流中取出楼梯操作，另外写楼梯数量及出现步号的间隔。例如楼梯在第 10、70、200 步，保存间隔减一 `9、59、129`，采用可变长整数；第一项相对第 0 步。其余方向仍只占 2 位。连续两次楼梯的间隔减一为 0，可以正常表达。

排列为：有楼梯才写的数量和间隔表 → 2 位方向流。最后记录末字节有几个空方向位置，用 2 位即可。方向数量由剩余字节和填充数量确定，总步数等于方向数加楼梯数，**不再重复保存总步数**。

### 5.2 楼梯多时的备选表示

少量短路线、尤其连续跨层时，楼梯表可能反而更长。为此保留一个简单备选：将上、下、左、右、楼梯对应为五进制数字 0～4，每三步打成一个 0～124 的值，只需 7 位；末尾一／两步分别用 3／5 位。

这比固定每步 3 位更省，也没有可变树或复杂自定义压缩器。编码时比较两种表示的原文和压缩结果，自动选最短；使用者不需要选择。

### 5.3 控制信息与地图绑定

完整操作码为：**1 字节控制信息 + 4 字节地图 CRC32 + 操作内容**，最后转成无 `=` 的 Base64URL。

控制字节最低位表示压缩，第二位表示使用哪种操作表示。采用方向流时，再写楼梯表存在标志和末字节空方向数量；采用五进制时，写末组一／两步情况和末字节零填充位数。其余位固定为零，非法组合拒绝。

为实现单一、确定的解码，具体位分配如下，位号从最低位 0 开始：

| 表示 | 控制位 |
|---|---|
| 两者共有 | 位 0：压缩；位 1：0 为方向＋稀疏楼梯，1 为五进制 |
| 方向＋楼梯 | 位 2：楼梯表是否存在；位 3～4：末字节空方向数 0～3；位 5～7 必须为 0 |
| 五进制 | 位 2～3：末组三步以外剩余操作数 0～2；位 4～6：末字节零填充位数 0～7；位 7 必须为 0 |

CRC32 对统一地图内容与开局设置计算，不对网址字符串计算；具体使用同图按 `00` 墙表示、未压缩、末尾补零排列后的内容。因此同一地图采用不同压缩文字，仍能匹配同一回放。CRC32 用 4 字节高位在前表示，它用于检出地图错配，不作为安全认证。

操作内容按需解压后，直接按标志还原。楼梯位置必须递增且不超过总步数；五进制组不能超过其合法数值；末尾填充必须为零。每步再由共同规则核验，若不能执行，指出发生问题的步，不悄悄跳过。

操作码不写地图副本、局面、探索位图、循环次数、规则版本、按键时间或缓存。没有旧操作格式兼容层。

### 5.4 本轮原型测量

| 《回环》70 步，无楼梯 | 27 字节 | 18 字节，不压缩 | 31 字符 |
| 70 个方向中再插入 3 次楼梯，共 73 步 | 28 字节 | 22 字节，不压缩 | 36 字符 |
| 单层 1000 步，先不考虑压缩 | 375 字节 | 250 字节 | 340 字符；可压缩路线会继续缩短 |

70 步的 18 字节方向数据单独转成文字是 24 字符；完整操作码多出的 7 字符承担控制和地图校验。它们是明确的功能开销，不是局面记录。

地图原型使用现有页面随附的 pako，比较原文和普通最高级别压缩，结果如下；正式实现还会加入游程策略比较：

| 《借位》 | 90 字符 | 60 字符 |
| 《回位》 | 116 字符 | 71 字符 |
| 按钮依附修正版 | 128 字符 | 79 字符 |

原型完成 25 份既有地图的三种墙表示往返，加一份 20×20、十层、生命和门槛 256 的边界样例，共 76 次内容核对；操作两种表示完成 192 次往返，覆盖 0～2000 步及不同楼梯比例。这些用于选择协议，不能代替正式实现的验收；其中历史撤回图的可编码性也不等于地图合法性。

## 6. 统一规则与秒加载

游玩、AI 搜索、训练环境和回放调用同一规则实现，AI 固定并核对本次规则基线。快速搜索可以保留自己的队列、状态索引和启发式，但不再单独实现移动、鬼、按钮、拾物、胜负或视野。既有快模拟的有效优化移入共同引擎，随后删除重复的规则实现。

这使每张 AI 地图的常规验收变成：地图合法性 → 新地图码往返 → 用共同引擎执行证书 → 到达正确胜利状态 → 生成操作码。无需每次再拿真实浏览器按整条路线重复验证。

浏览器验收安排在规则或界面交付时，覆盖代表性的单层／多层、两模式、方向键／点击／方向面板、URL 打开、回放和加载操作。出现相关交互回归或新增机制时才增加专项验收。可通关的自动验证不替代用户对谜题是否有趣的判断。

缩码和提速分别处理，不能把缓存当作首次加载的万能解法：

- 地图和操作码线性解析，只有被选中的表示被读取，加载端不执行“试哪个码更短”的工作。
- 打开回放先建立地图、第 0 步及播放控制，不为显示第一页预先推演整条路线。
- 共同引擎避免每一步复制整张地图：静态墙定义共用，只保存改变的门、物品、鬼与视野；动画记录留给显示。搜索的纯物理验证可省去显示用轨迹，物理决策仍来自同一引擎。
- 默认每 32 个有效操作保留一个临时局面，初态、当前态及存档点单独保留；最近一段局面用于快速撤回。临时缓存超过预算可释放，操作日志始终完整。
- 任意跳步先取最近较早缓存，再重放剩余操作；未缓存的远步分段推演，并在途中补缓存。切换全图无需重新推演物理过程。

临时缓存采用 16 MiB 的初始预算，实际结构共享部分不重复计入。存档标记不因缓存释放而消失，可由操作重建。更换地图、重来、死亡循环复活、加载回放后分别清理失效缓存。

验收要求为：在用户当前设备及本地已加载页面资源下，支持范围内地图开局首画面不超过 1 秒；代表性 1000／2000 步回放的冷跳步目标不超过 1 秒，已缓存跳步不超过 100 毫秒。超过目标先优化共同引擎和缓存，不能删校验、删动作或退回每步独立模拟器。网络下载时间另外记录。

本轮十层边界图的原型仅解析约 3 毫秒中位数，这说明编码不是主要瓶颈；它不包含界面、网络和规则推演，正式秒加载结论必须经过完整使用验收。

## 7. AI 地图集中交付

统一交付文件确定为本体的 **`docs/ai-map-catalog.md`**。它集中放地图名称、状态、来源、最新地图码、试玩链接、参考回放链接、当前规则下的步数和已知反馈，答案放在折叠区。

汇总范围包括已经交付的 AI 地图、已保存的历史候选、母图和机制对照；撤回版本也列出状态和后继版本。扫描 AI 的既有作品目录及保存的候选目录，不只列最近几张。搜索运行里的批量失败编辑留在实验档案，目录记录其来源，不复制成几万条可玩作品。

当前作品目录可识别到 25 份地图 JSON，其中有母图、对照和用户改图，不能直接称为 25 张正式 AI 作品。以统一地图内容去重，同一图的多个来源合并；保留用户改图的来源标记，撤回或质量反馈不覆盖原生成证据。

每个可交付条目都从原始地图数据生成新码，经解码往返与共同引擎重放后登记。参考证书能执行不代表当前规则下仍最短，最短步数只有重新证明后才标“最短”。撤回的非法图保留说明和原始来源，不生成虚假的可玩入口；修正版提供新码。

历史地图和录制文件作为证据保留；旧码不再用作有效交付入口，不保留为其服务的兼容逻辑。新的地图总目录、页面和生成工具全部只产出新格式。缺少完整动作的历史录制只转换能可靠还原的部分，不把推测动作冒称原始按键。

后续每次 AI 输出地图与最终证书，同时生成同页回放链接并更新这一文件。搜索分支不全部落盘；最终证书及明确需要保留的路线保存即可。真人路线、参考证书和测试路线保持来源可辨，不将测试数据混入真人记录。

## 8. 实施顺序与清理

1. **统一地图与规则。** 固定唯一各层定义与作者设置，取消体力，统一有效动作计步、出生／复活、视野和胜负；把快搜索的必要优化并入共同引擎，对齐 AI。
2. **实现新分享格式。** 完成两类码、地图绑定、边界校验和生成后内容往返；直接替换旧生成与读取，不搭建兼容层。
3. **贯通操作历史。** 在有效输入处记录动作，接上缓存、撤回、存档、两模式死亡恢复、本命边界和重来。
4. **完成同页回放。** 接入网址、自动播放、暂停、速度、选步、全图开关及确认加载，落实探索替换／死亡循环并集。
5. **拆出编辑器并整理界面。** 增加小导航入口，保留编辑草稿标签与试玩流程；主页统一模式标识和四项状态，取消红背景，更新帮助与文案。
6. **迁移与交付。** 全量整理地图总目录、重放有效路线、完成性能与代表性浏览器验收，并清理旧入口和废弃实现。

接替实现通过验收后，在同一轮删除其旧实现，不长期双轨运行。清理范围包括体力字段及剪枝、旧格式版本／读取器、重复规则模拟器、旧独立回放页面和录制编号播放链路、局面差分猜新动作的记录方式、主页编辑器分支、两套重复状态栏、红背景触发与样式、失效脚本和过期帮助。

AI 的历史录制导入与实验证据不能一并当作死代码删除；它们与运行时旧实现区分处理。继续保留本体的权威数据源和只读视图纪律，不引入新框架、构建工具、依赖或外部 AI 服务。

保护当前工作区已有修改；只在执行范围内接续修改，不回退其他人的文件。旧档出现数据冲突时明确列出，不能擅自猜一份覆盖另一份。

## 9. 完成验收

- 同图从编辑器试玩、URL 打开、重来、AI 和回放进入，地图、出生点、玩法与初始生命一致。
- 新地图码可以表达当前编辑器支持的结构；数字门、生命和实体数量不再截断，超过 255 字节的门参数可以完整往返。损坏或非法码干净失败。
- 有效动作与步数一一对应，原地按钮不漏记；五种操作能重建玩家、鬼、门、物品和胜负。删除临时缓存后结果仍一致。
- 两模式死亡恢复可用；复活与重来清理边界正确；不会读到上一命的存档。
- 回放链接脱离 AI 录制服务器也可打开；缺图、错配明确失败；速度、选步和加载可用，取消加载不改当前局。
- 探索加载替换视野；死亡循环加载使 6 变 7、旧探索与新路线取并集；同一轮撤回仍保留基础探索。全图开关不污染探索。
- 独立编辑页保留草稿标签，试玩正确；游玩页面仅有简单显示设置；两模式状态内容、鬼数、文案和背景符合要求。
- 本体与 AI 的相关测试、有效地图证书及新格式往返通过；性能达到第 6 节目标，再完成一次代表性浏览器交付验收。
- 主路径不再调用旧格式、体力、重复规则引擎或旧回放入口；历史证据保留，地图总目录只给最新有效入口。

## 10. 建议变化的依据

| 事项 | 之前为何那样考虑 | 现在为何改变 |
|---|---|---|
| 历史逐步存局面 | 任意恢复直接取快照，交互简单 | 已验证确定性操作能重建；用操作缩短分享，用临时缓存保留恢复速度 |
| 每步 3 位 | 五种动作直接统一编号，最容易实现 | 四方向占绝大多数，实际 70 步可从 27 降至 18 字节；稀疏楼梯加五进制备选兼顾单层与跨层 |
| 所有码都压缩 | 地图体积较大，通常压缩有效 | 原型中 18 字节方向压缩成 20 字节，一些小地图也膨胀；改为比较后选短者 |
| 保留旧 v3 读取 | 先前默认现有有效分享链接需要继续可用 | 用户明确弃旧；删除版本与兼容链路，将工作集中在新格式可靠性 |
| 编辑器同页 | 原结构如此，整理同页的改动量较小 | 编辑／游玩边界已明确且用户确定拆页；独立页面降低混用，另开标签自然保留草稿 |
| 记录旧探索 | 曾以还原录制者视野为目标 | 用户明确不需要；回放按自身路线推演，加载分别执行探索替换与死亡循环并集 |
| 保留快模拟后再验真 | 当前求解速度依赖独立快实现，末端重放可发现偏差 | 用户要求真正统一；将优化移入共同引擎，取消第二套规则，浏览器验收集中在交互交付 |
| 按钮不算步 | 现有步数偏向移动距离，与 AI 有效操作数不一致 | 按钮也会推进鬼，且用户已选择全部有效操作计步；统一后才适合作为未来评星依据 |

方案交付后的下一步是按第 8 节实施；本次未改游戏、AI 规则锁或原地图文件，未开始训练、生成新题、提交或推送。
